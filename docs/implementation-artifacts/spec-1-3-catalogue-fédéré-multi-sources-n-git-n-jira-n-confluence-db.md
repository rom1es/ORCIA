## Intent

**Problem:** ORCIA ne dispose pas encore du moteur du Catalogue Fédéré Multi-Sources permettant d'enregistrer et promouvoir des ressources à travers le cycle hiérarchique (`DRAFT -> SHARED_WORKSPACE -> SHARED_TEAM -> SHARED_BU -> PENDING_APPROVAL -> PUBLISHED_ORG`), de résoudre à la volée les URI (`db://`, `git://`, `nexus://`, `confluence://`, `jira://`, `orcia://`) vers le cache immuable `cas/<sha256>` en `< 50 ms`, d'appliquer la fusion déterministe des surcharges à 4 niveaux (`1. Base -> 2. Team [Arbre Équipe Parente -> Sous-Équipe] -> 3. Workspace [Solution Multi-Sources] -> 4. User`) avec génération de `run-lock.json`, d'importer sans perte des packs de skills BMAD (`SKILL.md` + `customize.toml` + `steps/*.md`), ni d'afficher le badge monospace `Federated URI & RBAC Badge` (`uri-badge`, `UX-DR8`) dans le module **📦 3. Catalogue Fédéré**.

**Approach:** Créer la révision Alembic `0003` (`catalog_items`, `workflow_definitions`, `workspace_customization_overrides` à clés primaires `UUIDv7`), implémenter dans `packages/orcia-core/catalog` le résolveur `FederatedUriResolver` (`cas/<sha256>` avec port de stockage objet compatible MinIO/S3 et cache chaud `< 50 ms`), le moteur `FourLayerOverrideMerger` (`Base -> Team -> Workspace -> User` + manifeste `run-lock.json` épinglant tous les triplets `(alias, uri, resolved_version, sha256)` du Workspace), l'adaptateur `BmadSkillPackAdapter` et le service `FederatedCatalogService`, exposer les routes FastAPI `/api/v1/catalog/*` et `/api/v1/cas/*`, régénérer `packages/api-client` en `0-diff`, et livrer dans `@orcia/ui` (`packages/ui`) et `apps/web` les composants `FederatedUriBadge` (`UX-DR8`) et `CatalogExplorerPanel` (`i18n` `fr`/`en`).

## Boundaries & Constraints

**Always:**
- Utiliser exclusivement `.venv/bin/` pour Python et maintenir `0` import `fastapi`, `sqlalchemy`, `dramatiq`, `redis` ou `litellm` dans `packages/orcia-core/domain`, `ports`, `permissions` et `catalog`.
- Créer la migration incrémentale `infra/migrations/versions/0003_story_1_3_federated_catalog_overrides_and_run_lock.py` (`down_revision = "0002_story_1_2"`) en SQL brut avec clés `UUIDv7` et tester `upgrade -> downgrade -> upgrade` sur PostgreSQL 18 (`testcontainers`).
- Protéger toute mutation du catalogue (promotion de portée, enregistrement de surcharge, import BMAD) par `ScopeAccessGuard` / rejet de `READ_ONLY_OBSERVER` (`HTTP 403 ERR_OBSERVER_MODE_READ_ONLY`).
- Garantir que la fusion à 4 niveaux (`Base -> Team -> Workspace -> User`) est pure et ne mute jamais la définition de base (`AD-14`), que la résolution sur cache chaud `cas/<sha256>` s'exécute en `< 50 ms` (`NFR-PERF-3`), et que chaque fichier reste sous `280–300` lignes avec une couverture unitaire $\ge 90\%$.
- Conserver l'isolation stricte de `packages/ui` (`@orcia/ui` sans `next/*`, `zustand`, `@orcia/api-client`, ni couleur hex hors `tokens.css`) et la parité `100 %` du dictionnaire `i18n` (`fr`/`en`).

**Never:**
- Ne jamais modifier les révisions Alembic `0001` et `0002` ni désactiver le trigger *Append-Only*.
- Ne jamais écraser un objet immuable déjà présent dans `cas/<sha256>` avec un contenu de hash différent (`ValidationDomainError` en cas de mismatch d'intégrité `SHA-256`).
- Ne jamais permettre une transition rétrograde ou invalide dans le cycle de publication (`DRAFT -> SHARED_WORKSPACE -> SHARED_TEAM -> SHARED_BU -> PENDING_APPROVAL -> PUBLISHED_ORG`).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Résolution d'URI fédérée & Cache CAS `SHA-256` (`< 50 ms`) | URI `git://`, `nexus://` (`.tar.gz`/`.zip`), `db://`, `confluence://<space>/<page>@v<N>`, `jira://<project>/<issue>` ou `orcia://` soumise à `FederatedUriResolver` / `POST /api/v1/catalog/resolve` puis `GET /api/v1/cas/{sha256}` | 1er appel (`cache_hit=False`) : calcule/vérifie `sha256`, stocke sous `cas/<sha256>` (en mémoire + MinIO `testcontainers`) ; appels suivants (`cache_hit=True`) : retourne l'objet depuis `cas/<sha256>` en `< 50 ms` | Schéma d'URI inconnu ou mismatch `expected_sha256` -> `ValidationDomainError` (`HTTP 422 ERR_VALIDATION_FAILED`) ; hash CAS introuvable -> `ResourceNotFoundError` (`HTTP 404 ERR_RESOURCE_NOT_FOUND`) |
| Promotion du cycle de vie du Catalogue (`FR-21`) | Appel `POST /api/v1/catalog/items/{resource_id}/promote` vers `SHARED_WORKSPACE`, `SHARED_TEAM`, `SHARED_BU`, `PENDING_APPROVAL` ou `PUBLISHED_ORG` | Met à jour `visibility_scope` de la ressource et de son entrée ACL lorsque l'appelant détient `ADMIN`/`EDIT` et que la transition est monotone croissante (`PUBLISHED_ORG` réservé à `PLATFORM_ADMIN` / `BU_DIRECTOR`) | Appelant en mode `READ_ONLY_OBSERVER` -> `HTTP 403 ERR_OBSERVER_MODE_READ_ONLY` ; transition rétrograde -> `HTTP 422 ERR_VALIDATION_FAILED` ; absence de droit -> `HTTP 403 ERR_SCOPE_ACCESS_DENIED` |
| Fusion déclarative à 4 niveaux & `run-lock.json` (`AD-5`, `AD-14`) | Workflow de base + surcharges `TEAM` (équipe parente puis sous-équipe), `WORKSPACE` (mapping multi-sources `3 git://`, `2 jira://`, `2 confluence://`) et `USER` | `FourLayerOverrideMerger` fusionne dans l'ordre `Base -> Team (Ancêtre -> Enfant) -> Workspace -> User` (scalaires écrasés, listes `rules`/`facts`/`datasources` concaténées sans doublon, `lenses` fusionnées par `code`) sans modifier l'objet de base, et génère `run-lock.json` avec les triplets `(alias, uri, resolved_version, sha256)` et `manifest_sha256` | `workspace_id` ou `workflow_uri` inconnu -> `HTTP 404 ERR_RESOURCE_NOT_FOUND` ; accès Workspace refusé -> `HTTP 403 ERR_SCOPE_ACCESS_DENIED` |
| Adaptateur BMAD (`BmadSkillPackAdapter`, `AR-5`) | Pack BMAD contenant `SKILL.md` (frontmatter YAML `name`, `description` + corps Markdown), `customize.toml` (variables/règles/lentilles) et `steps/*.md` (`step-01-...`, `step-02-...`) | Convertit sans perte le pack en `WorkflowDefinitionEntity` (`source_format="BMAD_PACK"`, étapes ordonnées avec instructions complètes, métadonnées `customize.toml` préservées et hash `SHA-256` épinglé dans `cas/<sha256>`) | Pack sans `SKILL.md` ou sans étape valide -> `ValidationDomainError` (`HTTP 422 ERR_VALIDATION_FAILED`) |
