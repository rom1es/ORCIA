## 1. Needs Analysis & Tech Lead Impact Study (Pre-Implementation)

### 1.1 Context & Problem Statement
- **Trigger**: `apps/web/src/features/admin/ai-models/aiModelsApiBridge.ts:48` originally used an inline ternary `locale === "fr" ? "…" : "…"` for a timeout error message, violating ORCIA's core i18n invariants:
  1. Zero user-facing UI strings or inline `locale === "fr" ? ... : ...` ternaries hardcoded in JSX, bridges, controllers, or `@orcia/ui` primitives.
  2. Strict **RFC 9457** `error_code` contract: backend routes return localized `problem+json` envelopes via `Accept-Language`, and client-only errors (timeout, network failure, generic abort) emit structured `ClientErrorCode` identifiers resolved in `apps/web` through the typed `fr`/`en` dictionaries (`apps/web/src/i18n/locales/`).
- **Additional Governance Requirement (2026-11-23)**: All agent chat conversations, documentation (`docs/`), Tech Lead reports, commit messages, and code comments/docstrings must be written in **English**, while the ORCIA web application (`apps/web`, `@orcia/ui`) and user-facing API responses remain **100% bilingual compatible in French (`fr`) and English (`en`)**.

### 1.3 Target Solution & Deterministic CI Architecture (4 Gates)
To make i18n and English-dev governance permanently non-regressible in CI (`AD-17` Layer 1a & 1b):
1. **Gate 1 (`apps/web/src/__tests__/i18n-hardcoded-locale-ast-audit.test.ts`)**: TypeScript/JSX AST scanner covering `apps/web/src` and `packages/ui/src` that bans inline `locale === "fr"` / `isFr ? ... : ...` ternaries and raw hardcoded user-facing JSX text/attributes outside `apps/web/src/i18n/locales/`, backed by a strictly decreasing ratchet baseline (`i18n-hardcoded-locale-baseline.json`) locked to `0` by Story `27.8`.
2. **Gate 2 (`apps/web/src/__tests__/i18n-dictionary-parity-and-jargon-audit.test.ts`)**: Verifies recursive `fr` ↔ `en` dictionary key-tree parity, interpolation placeholder (`{param}`) parity, zero empty strings, and zero banned internal ORCIA plumbing jargon (UX Rule 3.1).
3. **Gate 3 (`apps/web/src/__tests__/client-error-code-contract-audit.test.ts`)**: Enforces `ClientErrorCode` contracts in `*ApiBridge.ts`, `packages/api-client/src/`, and `formatRfc9457ErrorToBanner.ts` (zero raw user-facing error strings or locale ternaries).
4. **Gate 4 (`tests/unit/test_i18n_backend_catalog_and_english_dev_audit.py`)**: Verifies every backend `OrciaDomainError` / RFC 9457 `error_code` provides both `fr` and `en` localized copies (`Accept-Language`), bans hardcoded single-language LLM prompt directives outside `PROMPT_LOCALES`, and enforces English-only docstrings/comments on new and modified files (`git diff main...HEAD`).

## 2. Implementation Plan (Executed via Epic 27 — Stories `27.1`–`27.8`)

### 2.1 Data Schema & Alembic Migrations (`infra/migrations/versions/...`)
- No Alembic migration required: i18n dictionaries, `ClientErrorCode` resolution, and localized RFC 9457 catalogs operate in application/presentation layers without modifying persisted DB schemas.

### 2.2 Hexagonal Core, Orchestration & Workers (`packages/orcia-core/`, `apps/worker/`)
- Audit and remediate Categories B & D (`577` + `193` raw hits) across `packages/orcia-core` domain errors, `assistant_harness.py`, `assistant_governance.py`, `seeds.py`, and `orchestration_seeds.py` in **Story 27.7**.

- **Lot 0 (Story 27.1)**: Activate all 4 deterministic CI gates with measured ratchet baselines + shared client error helper.
