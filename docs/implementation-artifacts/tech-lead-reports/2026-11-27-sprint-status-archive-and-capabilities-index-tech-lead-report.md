## 1. Needs Analysis & Tech Lead Impact Study (Pre-Implementation)

### 1.1 Context & Problem Statement
- `docs/implementation-artifacts/sprint-status.yaml` has grown to `117,473 B` (`114.7 KB`, `1,684` lines), carrying `31` already-closed epics (`248` `development_status` keys) and `64` completed (`done`) `action_items`. Every BMAD workflow or orchestrator loading `sprint-status.yaml` pays ~30k tokens of historical noise.
- `docs/product/capabilities.yaml` has grown to `111,490 B` (`108.9 KB`, `1,209` lines, `66` capabilities). Agents looking up a `CAP-*` ID or checking coverage read or scan a large YAML registry instead of a compact index.
- Expected behavior:
  - Archive all `31` closed epics (`epic-1..12`, `epic-14..32`, where `epic-N: done` and 100% of stories are `done`, including their `done` or `optional` retrospective lines) and all `64` `done` `action_items` verbatim into `docs/implementation-artifacts/archive/sprint-status-epics-01-32-archive.yaml`, keeping only `epic-13` (`3` keys) and the `36` non-`done` `action_items` verbatim (`~36.7 KB`, `-69%`) in live `sprint-status.yaml` with 100% zero-loss parity.
  - Generate a deterministic `<= 10 KB` Markdown table index `docs/product/capabilities-index.md` via `scripts/generate_capabilities_index.py` (mirroring `scripts/generate_tlr_index.py`), regenerated by `pnpm site:sync` and checked by `pnpm site:check` and `.pre-commit-config.yaml` (never in Stage 1 `agent_check.py static`).

### 1.2 Consumer Audit, Schema Inspection & Constraints
- **Read-only consumer audit across `scripts/`, `infra/scripts/`, `tests/`, `.agent/skills/`, `.agents/`, `.github/`, `.pre-commit-config.yaml`, `docs/agent-playbooks/`, `package.json`, `AGENTS.md`**:
  - `sprint-status.yaml`: Zero Python scripts, tests, CI workflows, or pre-commit hooks read `sprint-status.yaml` directly (only text references in `scripts/tlr_index_legacy.json` and `apps/web/src/generated/orciaSiteManifest.ts`). Active consumers are BMAD skills (`.agent/skills/bmad-{build,code-review,correct-course,retrospective,sprint-planning,walkthrough}`) and agent playbooks (`AGENTS.md`, `coder.md`, `verifier.md`, `bmad-model-routing.md`). None require closed `done` epics or `done` `action_items` in the live file, provided header metadata (`generated`, `last_updated`, `project`, `project_key`, `tracking_system`, `story_location`) and status comments remain intact.
  - `capabilities.yaml`: Consumed by `infra/scripts/capabilities_registry.py`, `infra/scripts/sync_site_catalog.py`, `infra/scripts/uj_e2e_coverage.py`, and unit tests (`test_capabilities_registry.py`, `test_uj_e2e_coverage_gate.py`, `test_uj_prd_experience_consistency.py`, `test_site_catalog_sync.py`). Schema fields across all `66` entries (`66 live`, `65 runtime`, `1 failed_e2e` `CAP-042`): `id`, `title`, `origin`, `origin_ref`, `status`, `kind`, `verification`, `verified_at`, `uj`, `fr`, `db_tables`, `read_only_surface`, `e2e_exempt_reason`, `surfaces`, `tests`, `notes` (0 entries use an `e2e_specs` key; E2E specs are entries in `tests:` matching `apps/web/e2e/*.spec.ts`).
- **Approved constraints**:
  1. Verbatim preservation of all `36` non-`done` `action_items` (`~34.0 KB`) takes priority over a strict `<= 15 KB` target; resulting live `sprint-status.yaml` is `~36.7 KB` (`-69%`).
  2. All `31` closed epics (`epic-N: done` + 100% `done` stories, with `done` or `optional` retrospectives) are archived; only `epic-13` remains in live `development_status`.
  3. E2E specs count column counts `tests:` entries matching `apps/web/e2e/*.spec.ts` directly from `capabilities.yaml`.
  4. `.pre-commit-config.yaml` hook is scoped to `files: '^docs/product/capabilities(\.yaml|-index\.md)$'`.
  5. `AGENTS.md` must stay `<= 4,096 B` (`scripts/check_agent_rules.py`); every new/modified code/script/test/doc file must stay `<= 300` lines and strictly in English.
