# AD-24 — Hub des Modèles IA Fiable, Découverte Dynamique 0 Token, Test de Connexion Réel, Port Hexagonal d'Embeddings (`EmbeddingPort`) et Réindexation Sémantique Bloquante [ADOPTED]

> Verbatim detail moved from `ARCHITECTURE-SPINE.md` on 2026-11-27 (baseline `bf44884`). The condensed binding form lives in the spine; this file is the full rationale.

- **Binds:** `FR-14`, `FR-23`, `FR-28`, `FR-31`, `FR-33`, `NFR-SEC-1`, `NFR-PERF-3`, `NFR-TEST-1`
- **Prevents:** Faux sentiment de RAG sémantique causé par le hachage SHA-256 non sémantique, dérive silencieuse des identifiants de modèles obsolètes ou inexistants codés en dur (`gemini-argon`), tests de connectivité simulés à latence factice (18/42 ms) masquant les pannes réelles de clés ou d'accès réseau, dépendance à des SDK vendeurs tiers lourds, coexistence incohérente d'espaces vectoriels hétérogènes lors d'un changement de modèle, corruption ou ingestion silencieuse de chunks documentaires en l'absence de modèle d'embedding, et hallucinations de Mon Assistant lors d'une réindexation partielle ou non bloquante.
- **Rule:** L'accès aux modèles d'IA (chat, raisonnement et embeddings sémantiques) et le cycle de vie du corpus RAG appliquent 7 règles invariantes régissant le Hub des Modèles IA (`/settings/ai-models`), le routeur d'inférence et les indexeurs documentaires :
  1. **Zéro Nom de Modèle en Dur & Modale Épurée (D1, D4)** : Les champs de modèle principal et secondaire de la modale de configuration (`AiModelConfigModal`, `AiModelFormFields`) démarrent strictement à blanc (`""`). Les puces cliquables rapides pré-remplies sont supprimées. Des placeholders contextuels par fournisseur orientent l'administrateur sans imposer de modèle (Mistral : « ex. : mistral-large-latest » ; Ollama / vLLM : « ex. : llama3.2 » ; Gemini / OpenAI / Anthropic : « Identifiant exact publié par le fournisseur »). Côté backend, aucun endpoint fictif n'est seedé au Jour 0 (`DEFAULT_LLM_MODEL_ENDPOINT_SEEDS` purgé), `build_default_tier_mappings` retourne un tuple vide `()` tant qu'aucun modèle n'est configuré, et l'attribut `model_name` est obligatoirement renseigné sans valeur par défaut magique.
  2. **Découverte Dynamique des Modèles à 0 Token d'Inférence (`GET /api/v1/settings/ai-models/discover`, D2)** : L'API expose un endpoint agnostique interrogeant les endpoints de métadonnées des fournisseurs via `httpx.AsyncClient` partagé (`app.state.http_client`) sans consommer de tokens d'inférence : OpenAI / Mistral / vLLM / TEI (`GET /v1/models`), Ollama (`GET /api/tags` ou `/v1/models`), Google Gemini (`GET /v1beta/models` avec filtre sur `supportedGenerationMethods`). La clé d'API (saisie en modale ou lue depuis le coffre) transite uniquement côté serveur et n'est jamais renvoyée au client. Le champ de modèle devient une combobox filtrable alimentée à chaud tout en garantissant la saisie manuelle libre permanente. Tout endpoint fait l'objet d'un contrôle anti-SSRF strict (`is_safe_llm_endpoint_url`).
  3. **Test de Connectivité Réel & Éradication des Latences Factices (D3)** : La fonction simulée `evaluate_welcome_llm_connection_test` et les latences arbitraires (18/42 ms) sont supprimées du code. Tout test de connectivité déclenche un appel réseau réel mesuré en millisecondes : pour le chat, une complétion ultra-courte (`max_tokens=1`) validant l'authenticité de la clé et l'existence du modèle ; pour les embeddings, un appel sur texte court validant formellement que la dimension vectorielle retournée est égale à 1024. Toute erreur fournisseur (401, 403, 404, 429) est traduite en enveloppe RFC 9457 localisée avec code d'erreur explicite. En CI, un mock de transport HTTPX déterministe rejoue les réponses sans aucun coût (`0 $`).
  4. **Modèle d'Embedding Unique Actif GLOBAL & Port Hexagonal `EmbeddingPort` (D5, D6)** : Les enregistrements du Hub portent un attribut d'usage `usage: chat | embedding`. La plateforme autorise un et un seul modèle d'embedding actif à l'échelle globale (`GLOBAL`). La dimension imposée est strictement 1024 (colonne `halfvec(1024)` conservée dans PostgreSQL 18 sans migration de type). Les requêtes transmettent le paramètre de dimension réduite lorsque le protocole le permet (`dimensions: 1024` pour `openai_compatible` quand supporté [OpenAI text-embedding-3, TEI, vLLM], `output_dimensionality: 1024` pour `gemini_native` via `:batchEmbedContents`). Pour Ollama, le port privilégie l'endpoint standard compatible OpenAI `/v1/embeddings` ou natif récent `/api/embed` (l'ancien endpoint `/api/embeddings` déprécié est formellement exclu). Anthropic ne proposant pas d'API d'embeddings native est formellement exclu de l'usage embedding. L'activation d'un modèle d'embedding est rejetée si sa dimension vectorielle diffère de 1024. Le port `EmbeddingPort` (dans `orcia_core/ports/`) isole le domaine sans aucun SDK vendeur tiers (`openai`, `google-generativeai`, `anthropic` exclus) derrière des adaptateurs protocolaires HTTPX partagés (`openai_compatible` et `gemini_native`). Le câblage s'effectue exclusivement dans le Composition Root (`dependencies.py`).
  5. **Suppression Totale du Hachage SHA-256 en Production (D10)** : La fonction `compute_deterministic_halfvec_1024` est intégralement supprimée du code de production d'ORCIA. Le repli mémoire cosine de `hybrid_rag_service.py` et la recherche de `two_speed_search.py` consomment `EmbeddingPort`. En environnement de test et CI, un `FakeDeterministicEmbeddingAdapter` (`tests/unit/fakes/`) fournit des vecteurs enregistrés déterministes à coût nul (`0 $`).
  6. **Blocage Ciblé des Sources RAG sans Modèle d'Embedding, Découplage `Mon Assistant` & Préservation du Code Graph (D7, D11 — Amendé Epic 25 le 20/11/2026)** : En l'absence de modèle d'`embedding` actif GLOBAL (au Jour 0 après `pnpm db:reset`, ou après suppression du modèle), le rejet **`HTTP 422 ERR_NO_ACTIVE_EMBEDDING_MODEL`** s'applique **dès l'ajout (`POST /datasources`) et la synchronisation** de toute source documentaire nécessitant un RAG vectoriel (`source_nature != 'SOURCE_CODE'` : Confluence, Jira, Markdown, PDF, DDL — aucun chunk vectoriel ni index BM25 inséré), ainsi qu'aux endpoints directs de recherche/indexation RAG. En revanche : (a) les sources `SOURCE_CODE` (Code Graph Epic 18, GitNexus AST) restent totalement préservées (`embedding = NULL`, 0 token LLM, hors requête vectorielle) ; et (b) **`Mon Assistant` n'est PLUS bloqué** dès lors qu'au moins un modèle `chat` actif est configuré — l'`AssistantHarness` fonctionne en mode conversationnel direct + Rôle/Casquette + Glossaire/Ontologie SQL (sans interroger `pgvector`), accompagné d'un indicateur UI non-bloquant signalant l'inactivité de la recherche documentaire (avec lien vers `Administration › Modèles IA`).
  7. **Migration Alembic & Réindexation Bloquante Idempotente (D8, D9, D12 — Amendé Epic 25 le 20/11/2026)** : Une migration Alembic (`Expand -> Backfill -> Contract`) ajoute la colonne `kb_chunks.embedding_model_id` et passe les anciens vecteurs SHA-256 à `NULL`. Toute première configuration ou modification du modèle d'embedding actif déclenche un job Dramatiq idempotent de réindexation complète avec progression persistée (`rag_reindexing_jobs`), lorsque des documents indexés existent (côté UI, le bloc de réindexation vectorielle reste masqué tant que `0` document est indexé). Pendant toute la durée du job, la recherche RAG directe est totalement bloquée (`HTTP 503 RFC 9457 ERR_RAG_REINDEX_IN_PROGRESS` avec progression, aucun mode dégradé lexical ou Vitesse 1 toléré) et les nouvelles ingestions documentaires (`source_nature != 'SOURCE_CODE'`) sont suspendues en file d'attente, tandis que `Mon Assistant` demeure disponible en mode conversationnel + Rôle/Casquette + Glossaire/Ontologie SQL (sans `pgvector`) avec un indicateur non-bloquant de réindexation en cours.
  8. **Amendment Epic 26 (2026-11-21, D3 + D5 + R7 + R8 — 0-Token `supports_tools` Hub Discovery, 2 Native Tool Dialects & DNS-Pinned SSRF):** AI Hub 0-token metadata discovery probes native tool-calling capability to populate `supports_tools` (with explicit `PLATFORM_ADMIN` override persisted in PostgreSQL 18). All 3 `httpx` text and reasoning streaming adapters (`openai_compatible`, `anthropic`, `gemini_native` `CAP-076`) are preserved with strict `thinking`/`content` channel isolation, whereas native `tool_calls` streaming and non-streaming parsing/re-injection is scoped strictly to **2 dialects** (`openai_compatible` `delta.tool_calls` covering OpenAI, vLLM, Ollama `/v1`, Azure; and `anthropic` `tool_use` / `input_json_delta`). Native Gemini REST and non-`/v1` Ollama default to `supports_tools=false` (`HTTP 422 ERR_MODEL_TOOLS_UNSUPPORTED` on Speed 2/3, UI Speed 2/3 disabled, zero XML/ReAct emulation; future native parsers deferred to `ACTION_ITEM-26.4`). All Hub save, discovery, connection-test, and runtime model resolution paths enforce the DNS-pinned SSRF policy (`ORCIA_LLM_ALLOWED_PRIVATE_HOSTS` + `getaddrinfo`, `AD-21` Rule 7). Invariant `AD-24.6` remains unchanged: `"Mon Assistant"` stays unlocked once at least `1` active `chat` model is configured, even with `0` active `embedding` models.
