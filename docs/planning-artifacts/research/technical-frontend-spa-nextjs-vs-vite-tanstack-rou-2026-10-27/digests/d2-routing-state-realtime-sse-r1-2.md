## 2. Detailed Findings by Question

### Q1: Type-safe Routing & URL State (`TanStack Router v1` vs. `Next.js 15/16 App Router` vs. `React Router v7`)
* **Candidate B (`TanStack Router v1`)** treats URL query strings as a structured, hierarchical JSON state machine built into the router core `[D2-C1]`. Each route defines `validateSearch` (accepting Zod, Valibot, or ArkType via Standard Schema), which automatically parses, coerces, and defaults query parameters before loaders or components run `[D2-C1]`. `<Link to="..." search={...}>` and `navigate()` enforce compile-time type safety across the entire application `[D2-C1]`.
* **Candidate A (`Next.js 15/16 App Router`)** only types static and dynamic path segments via `typedRoutes` `[D2-C3]`. Native `searchParams` are passed as untyped `Promise<Record<string, string | string[] | undefined>>`, requiring external hook libraries like `nuqs` `[D2-C3, D2-C4]`.
* **Candidate C (`React Router v7` SPA mode)** uses `react-router typegen` to generate `+types/<route>.d.ts` files for path params and loader outputs, but search parameters accessed via `useSearchParams()` remain untyped raw strings `[D2-C2]`.

### Q2: Data Fetching (`@tanstack/react-query` v5, `openapi-fetch`) & Heavy Client Libraries (`@xyflow/react` v12)
* **Integration with `@tanstack/react-query` v5 & `openapi-fetch`:** `Vite 6 + TanStack Router v1` offers the tightest architectural fit: `queryClient` is injected via `createRouter({ context: { queryClient }, defaultPreloadStaleTime: 0 })` `[D2-C5, D2-C6]`.
* **Heavy Interactive Canvas Libraries (`@xyflow/react` v12 / React Flow):** In Next.js App Router, `"use client"` components still execute an initial SSR pass on the Node.js server, triggering hydration mismatches for DOM-measurement libraries like `@xyflow/react` unless wrapped in `next/dynamic(..., { ssr: false })` `[D2-C7]`. In `Vite 6 + TanStack Router` and `React Router v7 (ssr: false)`, `@xyflow/react` mounts directly in a single browser pass `[D2-C7]`.

### Q3: Real-Time SSE & Separate Backend Auth (`FastAPI` + `HttpOnly` Cookies)
* **Next.js Rewrites / Proxy Buffering Pitfalls with SSE:** Proxying `text/event-stream` through `next.config.js` `rewrites` has documented response-body buffering issues (`vercel/next.js` Issue `#45048`) `[D2-C8]`.
* **Vite Dev Proxy & Production Reverse Proxy:** In pure SPA architectures, Vite's dev proxy and production Nginx (`proxy_buffering off;`) forward FastAPI `StreamingResponse` SSE streams and `HttpOnly` cookies on a single origin without Node.js BFF hopping `[D2-C9, D2-C10]`.
