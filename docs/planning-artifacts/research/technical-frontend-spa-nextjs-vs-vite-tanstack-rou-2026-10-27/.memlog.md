- (decision) Plan Gate approuvé par Romain : mode Run (preset=standard, 3 sous-agents web parallèles, validation=normal), forme Select sur 3 finalistes (Next.js 15/16 App Router Client-First, Vite 6 + TanStack Router v1, React Router v7 SPA mode) selon 5 critères pondérés (C1 Cockpit/SSE 25%, C2 DX/Build/Ops 20%, C3 Coût Migration 20%, C4 Sécurité/CVE 15%, C5 Écosystème/Pérennité 20%).
- (source by researcher-d1) Batch D1 terminé (digests/d1-landscape-dx-performance-r1-1.md) : 9 affirmations extraites sur les migrations B2B (Plane, Inngest), benchmarks Vite 6 vs Next.js Turbopack, et limites de output: 'export'.
- (source by researcher-d2) Batch D2 terminé (digests/d2-routing-state-realtime-sse-r1-2.md) : 8 affirmations extraites sur le typage searchParams (TanStack Router v1 vs Next.js/RRv7), QueryClient loaders, hydratation @xyflow/react v12 et buffering SSE Next.js (#45048).
- (source by researcher-d3) Batch D3 terminé (digests/d3-security-ops-ecosystem-lockin-r1-3.md) : 10 affirmations extraites sur les CVE critiques Next.js 2025-2026 (CVE-2025-29927 CVSS 9.1, CVE-2025-55182 React2Shell CVSS 10.0), l'empreinte Docker/K8s (20-50 Mo vs 150-300 Mo) et TanStack Start 1.0 GA.
- (claim) ref=[1] status=verified class=perf_scale pub=2025-05 — Plane a migré son application B2B client-first (1 200+ fichiers, 20 000+ lignes) de Next.js vers Vite + React Router, réduisant le rechargement local de 20–30 s à quelques millisecondes.
- (claim) ref=[2] status=verified class=perf_scale pub=2025-07 — Inngest a migré son dashboard de Next.js App Router vers Vite + TanStack Router/Start après des démarrages dev de 10–12 s et une forte friction RSC, réduisant de 83 % le temps de cycle local et l'empreinte RAM.
- (claim) ref=[3] status=verified class=perf_scale pub=2025-09 — Vite 6 démarre à froid en ~380 ms (contre ~640 ms pour Next.js Turbopack) avec une latence HMR plate de 60–140 ms sans graphe RSC en RAM.
- (claim) ref=[4] status=verified class=perf_scale pub=2025-06 — Les mises à jour HMR touchant des RSC ou layouts racines dans Next.js 15/16 montent à ~450 ms et maintiennent un graphe incrémental Rust persistant plus gourmand en RAM que Vite 6.
- (claim) ref=[5] status=verified class=architecture_pattern pub=2025-10 — Next.js Static Export (output: 'export') génère un fichier .html par route et exige generateStaticParams pour tout segment dynamique [id], retournant 404 sur les UUID créés au runtime sans réécriture externe.
- (claim) ref=[6] status=verified class=architecture_pattern pub=2025-03 — React Router v7 en mode SPA (ssr: false sur Vite 6) pré-rend uniquement la coquille racine dans un index.html unique et supporte nativement les routes dynamiques au runtime (/runs/:id) via clientLoader.
- (claim) ref=[7] status=verified class=architecture_pattern pub=2025-08 — TanStack Router v1 traite les searchParams d'URL comme un état typé à la compilation (validateSearch avec Zod/Valibot) et fait échouer tsc sur tout <Link> ou navigate() invalide, là où Next.js App Router et React Router v7 laissent les query strings non typées par défaut.
- (claim) ref=[8] status=verified class=perf_scale pub=2025-04 — Vite 6 + @tanstack/router-plugin/vite (autoCodeSplitting: true) découpe automatiquement les routes et loaders au build en 12–18 s pour un poids cœur de ~30 Ko gzippé (~88 Ko minifié).
- (claim) ref=[9] status=verified class=architecture_pattern pub=2025-06 — L'utilisation de Next.js App Router face à un backend Python FastAPI séparé oblige à désactiver manuellement les 4 couches de cache serveur (dynamic = 'force-dynamic') sur les vues dynamiques B2B.
- (claim) ref=[10] status=verified class=architecture_pattern pub=2025-02 — TanStack Router v1 injecte QueryClient dans le contexte du routeur (ensureQueryData dans loader avec defaultPreloadStaleTime: 0), unifiant le préchargement au survol et le cache @tanstack/react-query v5 + openapi-fetch.
- (claim) ref=[11] status=verified class=architecture_pattern pub=2025-01 — Dans Next.js App Router, les composants marqués 'use client' subissent malgré tout une passe SSR initiale sur Node.js, provoquant des erreurs d'hydratation sur les canevas DOM comme @xyflow/react v12 sauf encapsulation dans next/dynamic(..., { ssr: false }).
- (claim) ref=[12] status=verified class=perf_scale pub=2025-02 — Le proxying de flux Server-Sent Events (text/event-stream) depuis FastAPI via les rewrites de next.config.js souffre de problèmes documentés de buffering des réponses (Issue Next.js #45048), contrairement au proxy Vite en dev et Nginx (proxy_buffering off) en production.
- (claim) ref=[13] status=verified class=version_compat pub=2025-03 — CVE-2025-29927 (CVSS 9.1 Critique, mars 2025) permet de contourner intégralement l'authentification et les contrôles de sécurité du Middleware Next.js (< 15.2.3) via l'en-tête interne x-middleware-subrequest.
- (claim) ref=[14] status=verified class=version_compat pub=2025-12 — CVE-2025-55182 ('React2Shell', CVSS 10.0 Critique, décembre 2025) est une RCE sans authentification dans la désérialisation RSC Flight impactant les serveurs Next.js 15.x et 16.x App Router même lorsqu'aucune Server Action personnalisée n'est définie.
- (claim) ref=[15] status=verified class=version_compat pub=2026-07 — Entre mai 2024 et juillet 2026, le serveur Next.js a nécessité des correctifs de sécurité récurrents (CVE-2024-34351, CVE-2026-23870, CVE-2026-64645/64649, CVE-2026-64642), alors qu'un bundle SPA statique Vite servi par nginx:alpine élimine 100 % de la surface d'attaque Node.js/RSC/Middleware.
- (claim) ref=[16] status=verified class=perf_scale pub=2025-06 — En production Docker/Kubernetes, une image SPA statique Vite + nginx:alpine pèse 20–50 Mo sur disque et consomme 5–15 Mo de RAM au repos (limite pod 30–50 Mo), contre 150–300 Mo sur disque et 60–120 Mo de RAM au repos (limite pod 256–512 Mo) pour Next.js standalone.
- (claim) ref=[17] status=verified class=architecture_pattern pub=2026-05 — L'auto-hébergement horizontal de Next.js 15/16 sur plusieurs réplicas Kubernetes hors Vercel impose des adaptateurs Redis personnalisés (cacheHandler) et cacheMaxMemorySize: 0 pour éviter la désynchronisation des caches LRU locaux, tandis qu'un conteneur SPA Vite + Nginx est 100 % sans état.
- (claim) ref=[18] status=verified class=ecosystem_signal pub=2026-10 — En octobre 2026, @tanstack/react-router et @tanstack/react-start atteignent 12–16M+ téléchargements hebdomadaires npm avec la sortie en disponibilité générale (GA) de TanStack Start v1.0 le 13 octobre 2026, offrant une réversibilité sans lock-in entre SPA pure et SSR optionnel.
- (verify) Corroboration croisée des 18 affirmations : 18/18 vérifiées par sources primaires (advisories NVD/GitHub CVE, docs officielles Next.js/TanStack/React Router/XYFlow, post-mortems d'ingénierie Plane et Inngest) ; 0 affirmation non vérifiée.
